# 별과 마법의 링크 턴제 전투 게임: 기획 + 프로토타입 로드맵

## Context
- 사용자 요청: "별·마법" 테마로 **팀을 편성하고, 마법과 마법을 이어(링크) 싸우는 턴제 게임**을 만들고 싶음. 이번 단계에서는 계획만 세움.
- 결정된 사항: **웹(TypeScript)**, **스토리 없이 전투 중심**, 범위는 **기획서 + 단계별 프로토타입 로드맵**.
- 저장소 `Amonds10/DRAS`는 비어 있음(커밋 없음). 재사용할 기존 코드가 없으므로 처음부터 구성함.
- 작업 브랜치: `claude/pensive-pascal-ml8y86`

## 1. 게임 디자인 (기획 요약)

**가제:** 성좌술사 (Starweaver)
**한 줄 요약:** 4명의 성좌술사로 팀을 짜고, 한 턴 안에서 마법을 **어떤 순서로 쏠지** 정한다. 앞 마법과 뒤 마법이 이어지면 밤하늘에 별자리 선이 그려지고 연쇄 보너스가 터진다.

### 1-1. 핵심 루프
1. **편성:** 로스터에서 4명을 골라 팀을 짠다. 화면에 팀의 링크 궁합이 미리 표시된다.
2. **전투, 계획 단계:** 적의 다음 행동(인텐트)을 보고, 아군 4명의 시전 순서와 마법, 대상을 정한다.
3. **전투, 실행 단계:** 정한 순서대로 시전한다. 앞 마법과 링크가 맞으면 체인이 이어지고 별자리가 그려진다.
4. **적 턴:** 적이 예고했던 행동을 한다.
5. 전투에서 이기면 보상(유닛 강화나 새 유닛)을 받고 다음 전투로 넘어간다. 짧은 런 형태로 진행한다.

### 1-2. 마법 링크 시스템 (핵심 메커닉)
- **성속(星屬) 5종:** 태양(Sol), 달(Luna), 성운(Nebula), 혜성(Comet), 공허(Void)
- 마법마다 **입력 성속**(받는 쪽)과 **출력 성속**(넘기는 쪽)이 있다.
  - 예: 「여명의 창」은 입력 아무거나, 출력 태양
  - 예: 「월광 베일」은 입력 태양, 출력 달
- **링크 판정:** 직전 마법의 출력이 이번 마법의 입력과 맞으면 링크가 성공하고 체인 수가 1 오른다.
- **체인 배율:** 1링크 ×1.0, 2링크 ×1.25, 3링크 ×1.6, 4링크(풀 체인) ×2.0 + 「성좌 완성」 보너스
- **성좌 반응:** 특정 성속 쌍이 이어지면 부가 효과가 붙는다.
  - 태양 → 달 = **일식**: 기절
  - 혜성 → 성운 = **유성우**: 광역 추가타
  - 달 → 공허 = **월몰**: 적 버프 제거
  - 성운 → 태양 = **초신성**: 방어 무시
  - 공허 → 혜성 = **블랙홀**: 적 인텐트 취소
  - 구현 단계에서 5~8종으로 확정한다.
- **마나(성진 Stardust):** 파티가 함께 쓰는 자원이다. 턴마다 회복하고, 강한 마법일수록 비싸다. "4명이 매 턴 모두 시전"과 "체인을 잇기 위해 일부러 건너뛰기" 사이에서 고민하게 만든다.
- **별자리 연출:** 전투 배경 밤하늘의 별 노드 위에, 링크가 하나 성공할 때마다 선이 그어진다. 풀 체인이면 별자리가 빛나며 완성된다.

### 1-3. 팀 편성
- 유닛 구성 요소: 역할(공격/방어/지원/교란), 기본 스탯(HP, 공격, 방어, 속도), 마법 2~3개(각각 입출력 성속을 가짐), 패시브 1개
- 편성 화면에서 4명을 고르면 가능한 링크 경로 수와 반응 종류를 미리 보여준다. 이것이 팀 빌딩의 재미가 된다.
- 초기 로스터는 12명이다(성속당 2명, 범용 2명).

### 1-4. 적 설계
- 다음 턴 행동을 아이콘으로 미리 보여준다(Slay the Spire 방식). 그래서 순서를 계획하는 데 의미가 생긴다.
- 링크 방해 기믹을 둔다. 예: 「성식(星蝕)」 디버프는 특정 성속 링크를 끊고, 보스는 체인 수에 비례한 반격을 한다.

## 2. 기술 구조

**스택:** Vite + TypeScript(strict) + PixiJS v8(별, 선, 파티클 연출) + Vitest(로직 테스트)
**원칙:** 전투 로직은 화면 렌더링과 완전히 분리된 순수 TS로 만든다. 그래야 테스트와 밸런싱을 헤드리스로 돌릴 수 있다.

```
DRAS/
├─ index.html
├─ package.json / tsconfig.json / vite.config.ts
├─ src/
│  ├─ core/                 # 순수 로직 (DOM/Pixi 의존 없음)
│  │  ├─ types.ts           # Element, Spell, Unit, Enemy, BattleState
│  │  ├─ rng.ts             # 시드 고정 난수 (재현 가능한 테스트용)
│  │  ├─ link.ts            # 링크 판정, 체인 배율, 반응 테이블
│  │  ├─ spell.ts           # 마법 해석(데미지, 버프, 상태이상)
│  │  ├─ battle.ts          # 턴 상태머신: plan → execute → enemy → check
│  │  ├─ enemyAI.ts         # 인텐트 생성과 실행
│  │  └─ team.ts            # 편성 검증, 링크 궁합 미리보기 계산
│  ├─ data/                 # 데이터 주도 콘텐츠
│  │  ├─ elements.ts        # 성속과 반응 정의
│  │  ├─ units.ts           # 12 유닛
│  │  ├─ spells.ts
│  │  └─ encounters.ts      # 적 구성, 스테이지
│  ├─ render/               # PixiJS: 밤하늘, 별자리 선, 이펙트
│  ├─ ui/                   # 편성 화면, 전투 HUD, 순서 드래그
│  └─ main.ts
└─ tests/core/*.test.ts     # link, battle, enemyAI 단위 테스트
```

## 3. 단계별 로드맵

| 단계 | 목표 | 산출물 | 완료 기준 |
|---|---|---|---|
| **P0 세팅** | 개발 환경 | Vite+TS+Vitest+ESLint/Prettier, `npm run dev/test/build` | 빈 화면 실행, 테스트 1개 통과 |
| **P1 전투 코어** | 헤드리스 전투 | `core/*`, 유닛 4명, 적 2종 | 콘솔/테스트로 전투 1판 완주, 링크와 체인 배율 테스트 통과 |
| **P2 최소 UI** | 플레이 가능 MVP | 전투 HUD(DOM), 순서 지정(드래그/번호), 인텐트 표시, 로그 | 브라우저에서 계획→실행→적 턴 루프 플레이 |
| **P3 별자리 연출** | 테마 구현 | PixiJS 밤하늘, 링크마다 선 그리기, 풀 체인 완성 연출, 반응 이펙트 | 링크 성공과 실패가 눈으로 구분됨 |
| **P4 팀 편성** | 빌딩 재미 | 로스터 12명, 편성 화면, 링크 궁합 미리보기 | 4명 선택 후 전투 진입, 미리보기 수치가 실제 결과와 일치 |
| **P5 콘텐츠·런** | 반복 플레이 | 일반전 3~5개 + 보스 1개, 승리 보상, localStorage 저장 | 첫 전투부터 보스까지 한 런 완주 |
| **P6 밸런스·폴리시** | 완성도 | 시드 고정 자동 시뮬레이션으로 승률 측정, 사운드, 튜토리얼 툴팁 | 주요 팀 조합 간 승률 편차가 허용 범위 안 |

**MVP = P0~P2.** 이 단계에서 "순서를 정해 마법을 잇는다"가 실제로 재미있는지 먼저 검증한다. 그다음 연출(P3)과 편성(P4)에 투자한다.

## 4. 검증 방법
- **로직:** `npm test`(Vitest). 링크 판정, 체인 배율, 반응 효과, 턴 상태 전이, 적 인텐트 실행을 단위 테스트한다. 난수는 시드를 고정해 결과가 재현되게 한다.
- **실행:** `npm run dev`로 브라우저에서 띄운 뒤 Playwright로 편성, 전투 1판, 승패 화면을 거치며 스크린샷을 확인한다(Chromium 사전 설치됨).
- **빌드:** `npm run build`가 타입 에러 없이 통과해야 한다.
- **밸런스(P6):** 헤드리스 시뮬레이터로 조합별 1,000판을 돌려 승률을 비교한다.
